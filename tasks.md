# Package pipeline simplification tasks

Complete these tasks in order. Scope: `openvox-packages` and the five source
forks named in `PLAN.md`. Preserve unrelated changes. Each task should leave a
reviewable change and pass its focused checks before proceeding.

Keep the existing coordinator, paired package versions, signing isolation,
anonymous candidate acceptance, promotion gate and previous-package retention.
Keep signature/hash rejection tests, version-ordering checks, unique local SSL
dependency coordinates, Bundler isolation, and meaningful cryptography checks.
Do not add a generic build framework, shared-action layer or retry framework.

## 1. Use native release commands and tag the tested coordinator revision

- [x] In `scripts/publish.sh`, replace explicit draft creation, release-ID lookup
      and publication PATCH with `gh release create`, retaining the explicit
      asset list and release notes, and using `--latest=false` and
      `--target "$GITHUB_SHA"`.
- [x] In `.github/workflows/packages.yml`, replace the promotion ID lookup and
      PATCH with `gh release edit "$CANDIDATE_TAG" --latest
      --notes-file RELEASE-NOTES.md`, after adding the acceptance marker.
- [x] Verify with the CI GitHub CLI version that asset-bearing creation stages
      uploads before publication. Keep publication and promotion separate.

Done when: focused command checks verify the target SHA and publication flags;
the final disposable-repository test proves complete candidate publication,
unchanged latest before acceptance, and explicit promotion afterward.
